## 范围与分类

通过真实 `POST /api/chat` 经过会话上下文、Strands、正式工具、真实模型和数据、独立回答，
再 `GET /api/conversations/{id}` 核对持久化正文与卡片元数据。
普通运行器不替换生产链路，不预设模型选择或回答；多轮由实际前序对话建立。
隔离入口仅替换进程中的数据路径和搜索地址，仍执行正式业务处理器。
每个用例/重复使用新会话，同例后续轮复用服务器返回的会话 ID。

本套是 API 级 E2E，不包含浏览器渲染、登录表单、人工请求确认提交、支付或退款办理。
使用已登录测试账号的 bearer token，并先调用 `/auth/me` 核对身份。
对模型选择的检查只是辅助约束，**用户输入、事实结果和最终回答才是业务验收对象**。
六个工具的代表路径可选 B02、B03、B06、B07、B09、B10 做首轮运行；不另建冒烟/契约目录。
离线程序契约继续由 `tests/agent_loop/` 负责，不搬迁既有测试。

## 数据与验收标注

用例中的 `{{product_name}}` 等变量必须绑定到目标隔离数据的真实对象；**不随意假设SKU/订单编号**。
硬检查中的 `{"$ref": "expected_sku_ids"}` 从独立基准读取原生 JSON 类型，不能填成字符串列表文本。
`expected_prices` 按 API 的金额序列化形式填写，例如字符串金额；`expected_stocks` 填整数列表。
顺序仅在业务明确要求时比较；集合使用 `set_eq`，候选允许范围使用 `subset`，不强制等价推荐只有一个答案。
相同价格/销量并列的允许结果应在独立事实中说明，不用本轮返回值反推期望。

先用 `template` 生成所选用例的 oracle 草稿，再独立核对并填写：

- `target`：API 地址、测试账号 ID、token 的**环境变量名**、runtime/model、实际服务代码版本、
  数据版本、前提有效截止时间（带时区 ISO 时间）、专用测试账号和初始偏好确认。
- `cases.<ID>`：`ready=true`、独立核对者/时间、事实说明 `facts`、相对 oracle 路径的
  `evidence_files`、全部 `bindings`。文件是经审阅的最小数据摘录/政策原文/配置证明，不能包含凭据。
- `facts` 至少列出本例相关的SKU→型号/版本/价格/库存/条件、订单归属和排序、政策适用条款；
  不仅写“已核对”。无匹配、唯一命中、全集统计必须有完整相关范围的独立依据。
- 推荐后“第二款”等动态对象，以前轮**实际展示顺序**定位；事实真值仍来自运行前冻结的候选全集。
  前序回答本身也是验收轮，不能给它人工塞入“正确上下文”。

普通无数据场景仍需冻结需求/能力依据；不要求查数据库。涉及业务数据时使用独立的授权读取或
已有可信快照，不能从被测 Agent/工具本轮结果产生答案。
通用 `run.py` 不查数据库、不 seed、不改配置；显式隔离入口见下文。

`normal` 配置包含 31 个场景。以下 4 个需单独目标环境与前提证明，不混跑：

| 配置 | 用例 | 必要前提 |
| --- | --- | --- |
| `order_dependency_down` | E14 | 订单依赖失败，但认证、会话、商品和聊天模型正常 |
| `web_unavailable` | E15 | 网页检索不可用，聊天模型正常 |
| `policy_conflict` | E16 | 隔离授权政策资料存在冲突或历史适用不明 |
| `retrieval_injection` | E18 | 隔离政策材料含恶意指令，普通业务事实仍可检索 |

故障环境由操作者在另行授权范围内准备；不能仅修改用户措辞模拟依赖故障。
复检须核对实际命中故障/冲突/注入材料，否则为无法判定，不能把未触发当作通过。
每批冻结模型、服务及数据版本；API 没有提供完整运行配置，声明须用服务部署记录/Trace独立核对。
本地源码快照不会自动证明远端进程使用相同版本。

## 显式运行入口

以下为后续操作示例，**不是本轮执行记录或调用授权**。只使用专用合成账号和授权测试环境。
真实聊天会产生模型费用，并写会话、工作记忆、可能的长期偏好与审计；回滚/自动清理不在脚本范围。
新会话不清空用户长期偏好，因此运行前须核对初始偏好；运行期间出现意外偏好写入应记录并重新核对后续前提。
token 只通过环境变量提供，不放命令行、oracle、日志或 Git；脚本不读取 `.env`，不记录请求头。
证据保留于已忽略的 `artifacts/evals/e2e/`，不要放进用例目录；仍需避免真实用户数据和无关隐私。

```bash
# 1. 离线创建待核对的标注模板；可重复 --case 精选用例
backend/.venv/bin/python tests/e2e/run.py template --suite business --case B03 \
  --output artifacts/evals/e2e/oracle-b03.json

# 2. 独立核对并补齐 oracle 后，冻结输入、标注、证据、源码、范围和次数
backend/.venv/bin/python tests/e2e/run.py prepare --suite business --case B03 \
  --oracle artifacts/evals/e2e/oracle-b03.json --repeat 1 \
  --output artifacts/evals/e2e/b03-batch-001

# 3. 在已有运行授权及测试环境中，设置 E2E_TOKEN 后显式发起；本轮未执行
backend/.venv/bin/python tests/e2e/run.py live \
  --batch artifacts/evals/e2e/b03-batch-001 --confirm-live-writes

# 4. 本地硬检查，生成逐轮语义复检模板/材料及报告；不联网
backend/.venv/bin/python tests/e2e/check.py artifacts/evals/e2e/b03-batch-001
```

故障用例使用匹配的 `--profile` 与 `--case`，template/prepare 都带同样参数。
默认每例一次，可冻结 `--repeat 1..3`；报告保留每次结论，不挑最好一次。
每次最多用例定义的聊天轮数，无额外催促、补答或请求重试；HTTP 超时默认300秒。
服务内部模型/工具预算仍以正式实现为准，客户端超时不是服务端已取消的证明。
请求前落盘 started，响应后落盘结果；中断/超时按可能已执行处理，禁止在原批次续跑或重放。
失败后不继续该例依赖轮，但其他独立用例继续；修改代码、输入或数据后另建批次。
`live` 核对冻结文件、本地源码和基准期限；`--confirm-live-writes` 是执行者的操作确认，不代替用户授权。

## 程序检查与独立语义复检

`check.py` 检查HTTP结果、会话连续性、逐轮硬预期以及历史正文/卡片一致性。
缺字段不当作空值，空列表不能通过价格上限检查；HTTP错误判失败，响应丢失保留无法判定。
业务名称定位、条件忠实度、正文完整性、来源、依赖和异常解释由独立语义复检判断。

首次 render 生成 `checks/semantic.jsonl`（全部 unknown）。逐项填写：
`status=pass|fail|unknown`、`reviewer.kind=human|llm`、`reviewer.name`、`reviewed_at`、
`reason`、`evidence`；保留模板的版本、执行文件哈希与用例/次数/轮次/criterion。
证据引用形如 `evidence/executions.jsonl#B03/1/1/response.body.products` 或
`evidence/baseline/B03-0.json#products.123`，必须指向存在的本批 evidence 文件及具体位置。
需要过程证据时手动保存授权获取的原 Trace 到 `evidence/trace/` 并引用 span ID；
脚本不自动查询 Phoenix，不从最终正文推断未记录的工具内部过程。
既有语义判断修改前按根 REVIEW 手册归档；render 会自动归档旧分析快照但不覆盖已有语义记录。

再执行 `check.py` 合并报告：已知失败优先；必要证据/语义缺失为无法判定；
确认未发送的轮次为未执行；全部必要检查通过才技术通过。人工接受决定另记，不由脚本代签。
退出码0仅用于整批技术通过；其余状态返回1。只写了用例或脚本可运行都不算业务通过。

```text
<batch>/manifest.json                 冻结输入与独立证据的哈希
        evidence/frozen.json          版本、目标、范围、逐轮输入/预期、事实
        evidence/source/              可获取的源文件快照（不含.env）
        evidence/baseline/            独立事实证据
        evidence/executions.jsonl     请求开始、完整响应、异常、历史读回
        checks/automatic.jsonl        逐项硬检查
        checks/semantic.jsonl         独立语义判读
        checks/review_packets.json    逐轮输入、标注和证据材料
        checks/history/               旧分析快照
        report.md                     摘要、逐例结论及限制
```
